# Dontanello

Личный ассистент: Notion подключён через локальную интеграцию. Python 3.10+, стандартная библиотека Python; анализ отчётов через Groq.

Правила развития: [архитектура](docs/architecture.md), [решения](docs/decisions/0001-modular-monolith.md). Постоянные инструкции для coding agents: [AGENTS.md](AGENTS.md).

## Структура

```text
src/dontanello/
  modules/completion/    # правила выполнения, контракты, адаптеры
  modules/reports/       # отчёты, календарное расписание, журнал доставки
  modules/operations/    # резервные копии, ошибки и восстановление
  integrations/         # транспорт Notion, Telegram и Groq
  entrypoints/          # CLI и polling worker
  platform/             # настройки, часы, блокировка процесса
  bootstrap.py          # сборка зависимостей
tests/
  unit/                 # сценарии без сети
  contracts/            # преобразование API и хранение состояния
  architecture/         # границы импортов и отсутствие циклов
config/settings.json    # источники и имена полей
deploy/systemd/         # сервис автозапуска
scripts/                # вспомогательная диагностика
docs/                   # архитектура и история решений
state/                  # локальное состояние; исключено из Git
assistant.py            # совместимый запуск для текущего сервиса
pyproject.toml          # пакет, инструменты и зависимости
```

Новые возможности добавляются отдельными модулями по назначению. HTTP payload остаётся в адаптерах; сценарии получают типизированные зависимости. Между модулями разрешены только публичные контракты. Микросервисы можно выделить позже при конкретной необходимости.

## Разработка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
make check              # Ruff + mypy + все тесты
make test               # тесты, включая архитектурные, без сети
make format             # форматирование и исправления Ruff
.venv/bin/dontanello --check --root "$PWD"
```

Python-код установлен из `src/`. При запуске установленного CLI из другой папки указывайте `--root` с каталогом конфигурации и `.env`. Runtime не требует сторонних Python-пакетов; Ruff и mypy нужны для разработки. Systemd запускает совместимый assistant.py через /usr/bin/python3.

Включите проверку секретов: `git config core.hooksPath .githooks`. Перед коммитом и отправкой запускайте `python3 scripts/check_secrets.py`; при ошибке остановитесь и уберите секреты из индекса. В `.env.example` поля токенов всегда пустые.

## Даты выполнения

Сервис проверяет Notion каждые 30 секунд:

- Tasks Table: включение `Сделано` или `Готово` → текущая дата в `Completed On`.
- Goals: включение `Checkbox` → текущая дата в `Completed on`.
- Часовой пояс: `Asia/Bishkek`.

Первое чтение сохраняет начальное состояние, не изменяя даты уже выполненных записей. Снятие галочки сохраняет дату; повторное выполнение обновляет её. Существующая дата обновляется при новом включении галочки. Один и тот же источник целей, показанный на нескольких страницах, отслеживается один раз.

Это опрос, а не webhook: быстрое включение и снятие галочки между проверками может быть пропущено. Дата соответствует обнаружению выполнения; при длительном отключении компьютера она может отличаться от фактического дня выполнения. Для постоянной работы компьютер должен быть включён, иметь доступ к интернету и активный пользовательский systemd.

## Управление

```bash
python3 assistant.py --check  # проверка доступа и схемы, без записи
python3 assistant.py --once   # один цикл
python3 assistant.py          # непрерывная работа
make test
systemctl --user status dontanello.service
journalctl --user -u dontanello.service -n 30
systemctl --user restart dontanello.service
systemctl --user stop dontanello.service
```

Файл `deploy/systemd/dontanello.service` можно подключить командой `systemctl --user enable --now "$PWD/deploy/systemd/dontanello.service"`. Он настроен на текущий абсолютный путь проекта и сохраняет совместимый запуск через `assistant.py`.

## Настройки и Telegram

Секреты лежат в `.env` с правами `600`, файл исключён из Git. Образец без секретов: `.env.example`. Базы и имена полей заданы в `config/settings.json`; рабочая база сохранена для будущих отчётов, её записи сейчас не меняются. Переменные окружения имеют приоритет над `.env`.

Для Telegram нужны `TELEGRAM_BOT_TOKEN` из @BotFather и `TELEGRAM_CHAT_ID`. `python3 assistant.py --check` проверяет бота, получателя и поля источников отчётов без отправки сообщений. Команды обрабатываются только в настроенном личном чате.

`TELEGRAM_CHAT_ID` — положительный ID личного чата: групповой ID отклоняется при запуске, чтобы личные отчёты нельзя было случайно направить в группу. Будущие возможности для пары потребуют отдельного профиля группы с собственными данными и командами; сейчас они не реализованы.

Команды: `/week` — обзор прогресса за предыдущую полную неделю, `/month` — Monthly Progress Review за предыдущий календарный месяц через Groq; `/week full`, `/month full` — полный сырой список; `/status`, `/help`. Недельный обзор сначала показывает главное изменение и конкретные результаты, затем навыки и подтверждённые сравнения, внешние зависимости и максимум пять следующих шагов. Идеи вынесены отдельно. Месячный обзор анализирует трансформации, движение проектов, накопленные навыки и повторяющиеся наблюдения по исходной истории месяца и архиву, а не соединяет недельные тексты. Рабочая активность не означает завершение задачи; отменённые задачи исключены.

В `.env` используются существующие `GROQ_API_KEY` и `GROQ_MODEL=openai/gpt-oss-120b`. Для автоматического переключения при исчерпании квоты можно задать `GROQ_API_KEYS` — список дополнительных ключей через запятую. Основной ключ проверяется первым; повторяющиеся ключи исключаются, общий предел — десять. Название модели содержит `openai/`, но запросы идут только в Groq; отдельный ключ или доступ к OpenAI API не нужен. Weekly и Monthly используют разные стратегии одной модели; небольшому входу достаточно одного запроса. Большие периоды обрабатываются последовательными пакетами, затем модель объединяет компактные проверенные выводы и точные цитаты в итоговый обзор. Каждый текущий факт передаётся в анализ; пакеты не являются subagents. Извлечение пакетов использует reasoning low; итоговый Weekly — medium, Monthly — high. `reports.ai` в `config/settings.json` ограничивает полный prompt каждого пакета 10000 символами, число пакетов — 24, все попытки модельных вызовов, включая неуспешные попытки с разными ключами, — 48, адресные исправления одного анализа — тремя обращениями. Общий вход ограничен 160000 символами, ответ — 3000 токенами, история — 80 записями, ожидание — 180 секундами на запрос. Подробности: [ADR 0005](docs/decisions/0005-groq-progress-analysis.md).

Все текущие записи передаются модели без отбрасывания ранних событий. Для большого входа каждый пакет сначала анализируется и проходит проверку цитат и структурных правил; итоговый синтез по проверенным выводам проходит те же проверки перед сохранением. Эти проверки подтверждают происхождение цитат и соблюдение правил, но не доказывают автоматически истинность любой интерпретации модели. Исторический контекст содержит ограниченную подборку исходных доказательств, начальные и конечные состояния проектов и подтверждения из snapshots архива; прежний сгенерированный текст не является независимым доказательством. Обычный подтверждённый ответ завершает анализ после одного запроса. Адресные исправления ограничены общим бюджетом; при его исчерпании сохраняется только подтверждённая часть с сообщением об ограничении. Слишком большой вход явно отклоняется, а не молча обрезается. При сбое Groq отчёт не заменяется сырым списком. Сетевые ожидания и повторы ограничены. При явном HTTP 429 ключ временно исключается по Retry-After, клиент проверяет следующий доступный ключ и сохраняет успешно работающий ключ для следующих запросов. За один вызов каждый ключ проверяется максимум один раз; все попытки входят в общий бюджет. Переключение не выполняется при сетевой неопределённости или серверной ошибке. Если все ключи ограничены, сценарий завершает попытку с ограниченной ошибкой; ожидание внутри анализа не превышает 120 секунд. Временные ограничения ключей хранятся только в памяти: после перезапуска основной ключ проверяется снова. Ключи одной организации могут разделять общую квоту. Квоты бесплатного аккаунта Groq могут ограничить генерацию; автоматического перехода на платный тариф или другого поставщика нет. При отсутствии записей обучение и сравнения показывают честный пробел без оценки продуктивности.

Расписание включено в `config/settings.json`: понедельник 09:00 — прошлые понедельник–воскресенье; первое число 09:00 — предыдущий календарный месяц. Часовой пояс берётся из `.env`. Если компьютер был выключен, сервис догоняет только последний наступивший период каждого типа после даты активации, без пачки исторических отчётов.

Структурированные Weekly/Monthly обзоры и фактические метрики анализа (запросы и доступные данные об использовании токенов) сохраняются в `state/progress.sqlite3`: исходные факты, цитаты, разделы, период и версии схемы/стратегии. Повтор за тот же период возвращает сохранённый обзор. История разделена по личному чату; предыдущий сгенерированный текст не считается новым доказательством. Исторические данные ограничены последними двенадцатью месяцами; недостаток истории отмечается явно. Новые квартальные и годовые стратегии пока не реализованы. Подробности: [ADR 0004](docs/decisions/0004-progress-reviews.md).

Текст и части сообщения сохраняются в `state/reports.sqlite3` до отправки. Подтверждённые части не повторяются. Явный отказ Telegram повторяется не раньше пяти минут. Потеря подтверждения помечается `uncertain`: автоматический повтор остановлен, требуется ручная сверка, количество таких частей видно в `/status`. Старый ожидающий период не догоняется после наступления нового. Удалять журнал для «повторного запуска» нельзя: это может повторить отправленные сообщения.

Предпросмотр без отправки (смысловой обзор сохраняется в архив и повторно используется):

```bash
python3 assistant.py --preview-report week
python3 assistant.py --preview-report month --full
```

## Копии и уведомления

Копия создаётся при первом цикле дня, затем проверяется каждый час. Хранятся последние 14 корректных дней в `state/backups/YYYY-MM-DD`. В копии входят состояние чекбоксов, уведомлений, позиция Telegram, SQLite-журнал доставки, структурированный архив прогресса и конфигурация. `.env` и токены не копируются. Повреждённая копия не вытесняет корректную. Это локальные копии: от потери диска они не защищают.

Проверка и восстановление:

```bash
python3 assistant.py --verify-backup YYYY-MM-DD
systemctl --user stop dontanello.service
python3 assistant.py --restore-backup YYYY-MM-DD
systemctl --user start dontanello.service
```

Восстановление проверяет контрольные суммы, подготавливает файлы до замены и требует свободной блокировки worker. Существующая история отправки сохраняется по умолчанию. Флаг `--restore-delivery-history` явно разрешает её откат и может повторить сообщения, отправленные после даты копии. `.env` не изменяется.

Ошибки заданий и восстановление приходят в Telegram, повтор ошибок ограничен одним часом и сохраняется между перезапусками. При недоступном Telegram уведомления могут задерживаться; после неоднозначной доставки уведомления возможен ограниченный повтор. Подробные ошибки остаются в `journalctl`. Независимые группы выполняются параллельно, источники completion — последовательно.

Не удаляйте `state/checkboxes.json`: это память предыдущего состояния. После удаления следующий цикл снова создаст исходный снимок.

При переносе кода сохранена резервная копия `state/checkboxes.pre-refactor.json`. Вспомогательная диагностика баз: `python3 scripts/inspect_notion.py` (только чтение).

API: [документация Notion](https://developers.notion.com/reference/retrieve-a-database).
