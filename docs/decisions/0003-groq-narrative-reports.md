# 0003: Смысловые отчёты через Groq

Дата: 2026-09-28. Статус: принято. Пересматривает отображение отчётов из ADR 0002.

## Контекст

Пользователь отклонил сводку из количества строк и последних десяти записей: повторяющиеся рабочие логи не объясняют результаты недели. Пользователь явно поручил использовать Groq.

## Решение

Отчёт по умолчанию формируется NarrativeReports через порт SummaryGenerator. Groq — внешний адаптер и HTTP-клиент. Все записи периода читаются и дедуплицируются до генерации; compact top-10 не используется как вход модели. Повторяющиеся рабочие записи группируются по проекту/REP ID, уникальные детали сохраняются. Большие входы обрабатываются ограниченными пакетами с последующим объединением фактических заметок. При превышении лимита или сбое отправка отчёта завершается ошибкой, без скрытого отсечения данных или замены на сырой список.

Настроенная доступная модель: `openai/gpt-oss-120b` через Groq; имя задаётся в GROQ_MODEL, секрет — GROQ_API_KEY. Не производится скрытый переход на другую модель. Только текстовый ответ, без вызова инструментов или выполнения действий. Текст Notion рассматривается как исходные данные, а не инструкция. Период, факт активности/выполнения и зарегистрированные ограничения передаются модели явно.

Рабочие факты сохраняют точное время записи для определения последовательности изменений. Промежуточные заметки сохраняют эту хронологию; даты в заголовке итогового отчёта формирует код. Название проекта и идея не доказывают начало разработки, а название поля «Следующий шаг» не исключает уже выполненную работу. Модель учитывает конкретные свежие обновления и обозначает противоречия.

Пакет входных данных ограничен 10 000 символами сериализованного JSON, максимум 12 исходных пакетов. Длинные записи делятся с учётом JSON-экранирования без обрезания текста. Промежуточные заметки ограничены 4500 символами с одной попыткой сокращения; тело итогового отчёта — 3300. Транспорт: тайм-аут 45 секунд, до двух повторов HTTP 429/503, Retry-After не более 120 секунд. При отсутствии заголовка ожидание составляет 30 секунд для 429 и одну секунду для 503. Генерация работает в независимой группе заданий.

Итог — короткий русский отчёт о конкретном продвижении по проектам, результатах и записанных следующих шагах. Рабочие события не объявляются завершёнными задачами. Пустые разделы, сырые временные отметки и ссылки не заполняют отчёт. При отсутствии записей используется честное сообщение об отсутствии данных, без вывода, что пользователь ничего не делал.

Полный сырой список доступен через `/week full` и `/month full`. Отправленный текст сохраняется журналом; безопасные повторные попытки используют его без нового запроса к Notion или Groq.

## Последствия

Для смысловых отчётов требуется доступный Groq API. Названия и содержимое записей выбранного периода передаются Groq по поручению пользователя. LLM может ошибаться в интерпретации: исходные записи сохраняются в Notion, полный список доступен для сверки. Генерация изолирована от исполнения действий и не управляет календарём или отметками задач.
