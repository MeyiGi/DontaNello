# ADR 0005: ограниченный анализ прогресса через Groq

## Контекст

Для Weekly/Monthly нужны смысловые обзоры с проверяемыми цитатами и историческими сравнениями по [ADR 0004](0004-progress-reviews.md). У пользователя уже настроены Groq и `openai/gpt-oss-120b`; отдельного ключа OpenAI API и бюджета для него нет. Поэтому deployed runtime использует Groq. Реальные периоды содержат десятки тысяч символов исходных данных; бесплатная квота `openai/gpt-oss-120b` ограничивает токены в минуту ([Groq rate limits](https://console.groq.com/docs/rate-limits)), поэтому один большой prompt не подходит каждому периоду. Предпочтение Sol для coding agents относится к разработке и не определяет поставщика runtime API.

## Решение

Три отдельные ответственности:

1. **Анализ:** Groq adapter передаёт небольшой вход и scoped history в один запрос к настроенной модели. Большой период разбивается на ограниченные последовательные пакеты: извлечение выводов → проверка → итоговый синтез по компактным проверенным выводам и точным цитатам → проверка → сохранение. Каждый текущий факт передаётся в один из пакетов без молчаливого пропуска. Пакеты не являются агентами. Ответ запрашивается по строгой структурированной схеме. Native multi-agent, API tools и дополнительные SDK не используются. Если проверка обнаружила спорный вывод, адаптер может запросить адресное исправление в пределах общего бюджета.
2. **Progress intelligence:** общий pipeline собирает факты, состояния и точные цитаты; Weekly/Monthly стратегии задают разные вопросы. Приложение проверяет происхождение цитат, периоды, проекты, хронологию и допустимость статусов на этапе пакетов и итогового синтеза. Эти guards не являются математическим доказательством истинности смысловой интерпретации модели. Текст прежнего отчёта не становится независимым доказательством.
3. **Presentation:** deterministic renderer оформляет подтверждённые выводы по структуре пользователя. Delivery и scheduling сохраняют существующие ключи и календарные правила.

Порт `ProgressAnalyzer` принадлежит reports; адаптер Groq реализует его. HTTP transport остаётся в integrations/groq, настройки и конкретные зависимости связывает bootstrap. Business code не зависит от Groq payload, HTTP или credentials. Стандартной библиотеки Python достаточно для runtime; systemd сохраняет запуск `/usr/bin/python3 assistant.py`.

## Память и доказательства

Все исходные факты текущего периода сохраняются в локальном структурированном архиве. Контекст сравнения строится по исходным записям и состояниям проектов из уже авторизованной области личного чата. История ограничена предыдущими двенадцатью месяцами; модель получает подборку исходных доказательств, начальных и конечных состояний проектов и подтверждений из snapshots. Новый snapshot хранит текущие записи и цитируемые исторические доказательства, избегая копирования всего года в каждый документ. Отсутствие истории отмечается явно.

## Бюджеты и остановка

`reports.ai` задаёт 10000 символов полного prompt пакета (`max_batch_chars`, включая инструкции, schema и payload), максимум 24 пакета (`max_batches`) и 48 попыток модельных вызовов всего (`max_requests`, включая extraction, correction, synthesis и неуспешные попытки каждого ключа). `max_rounds=3` ограничивает обращения одного анализа с адресными исправлениями. Общий вход ограничен 160000 символами, ответ — 3000 токенами, история — 80 записями, ожидание — 180 секундами на запрос. Извлечение пакетов использует reasoning low; итоговый Weekly — medium, Monthly — high. Итоговый синтез и его исправления входят в общий бюджет; небольшой вход не разбивается и обычно завершает анализ за один запрос. Первый подтверждённый ответ завершает анализ. Ограничения применяет приложение; модель не создаёт subagents. Превышение входного бюджета не обрезает текущие факты молча. При исчерпании анализа сохраняется проверенное подмножество с явным сообщением об ограничении. Неподтверждённые выводы не сохраняются как факты; если проверенного ответа нет, архив остаётся неизменным и сценарий сообщает ошибку.

Сетевые ожидания и retry budget ограничены. Structured transport не скрывает повторы за анализатором: все попытки ключей и ответы 429 учитываются в общем бюджете, адресные повторные обращения ограничены `max_rounds`. Ожидание внутри анализа ограничено 120 секундами и выполняется короткими интервалами. Неоднозначный сетевой результат не вызывает немедленного replay. Повтор задания позже возможен по существующей политике scheduler; журнал доставки защищает подтверждённые сообщения. Метрики запросов и доступные данные использования токенов сохраняются с документом и не являются оценкой продуктивности пользователя. Ни cache hit, ни бесплатность или доступность тарифа не предполагаются. Квоты бесплатного аккаунта могут ограничить генерацию даже при пакетной обработке; автоматического платного upgrade или перехода на OpenAI API нет.

## Переключение ключей и восстановление

При явном HTTP 429 transport временно исключает текущий ключ на срок Retry-After и пробует следующий доступный ключ. За один вызов каждый ключ проверяется максимум один раз. Успешный ключ остаётся активным для следующих запросов. Пул и сроки временных ограничений защищены от одновременного доступа и хранятся только в памяти; после перезапуска основной ключ может быть проверен повторно. Отдельное долговечное хранилище индексов ключей не вводится, ключи не логируются.

Сетевая неопределённость и 5xx не переключают ключ: автоматический replay мог бы повторить уже принятый запрос. Если все ключи ограничены, transport сообщает ограниченную ошибку; неподтверждённый результат не сохраняется и сырой fallback не отправляется. Несколько ключей одной организации могут разделять квоту, поэтому пул не гарантирует обход лимита или время восстановления.

## Развёртывание и последствия

Используются существующие `GROQ_API_KEY` и `GROQ_MODEL=openai/gpt-oss-120b` в `.env`. Необязательный `GROQ_API_KEYS` содержит дополнительные ключи через запятую. Пул сохраняет порядок, начинает с основного ключа, удаляет повторы и ограничен десятью ключами. Все credentials остаются только в локальном `.env`. Название модели содержит `openai/`, но транспорт обращается к Groq; ключ OpenAI API, OpenAI SDK и Responses API не нужны. Credentials в `.env.example` остаются пустыми. `.env`, исходные личные записи и архив не попадают в Git.

Смена поставщика анализа не меняет контракты фактов, архив, разрешения, периоды или идентичность доставки. Ошибка Groq не заменяется сырым списком; `/week full` и `/month full` остаются явными диагностическими командами. Offline tests проверяют правила и HTTP-контракт без записи в личные данные; живой smoke check проводится отдельно.
