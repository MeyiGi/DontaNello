# 0009: Groq routes ordinary Telegram messages

Дата: 2026-10-04. Статус: принято.

## Контекст

Inbox, Tasks, Google Calendar и напоминания принимали свободный текст через отдельные распознаватели и цепочки условий. Из-за этого обычное сообщение могло попасть в Inbox только потому, что пользователь перед этим нажал кнопку, а пользователь должен был помнить формулировку для конкретной функции.

## Решение

Добавить capability `message_intent` с портом интерпретатора и Groq-адаптером. Telegram отправляет обычный текст в один вызов настроенного Groq-моделя. Результат содержит destination, confidence, нормализованный текст и при наличии явную дату задачи. Команды, inline-кнопки и продолжения уже начатых диалогов остаются детерминированными.

Root Telegram entrypoint передаёт предложенный intent через компактную таблицу обработчиков в публичные application contracts Inbox, task capture, calendar planning и reminders. LLM не выполняет API-запись. Низкая уверенность, повреждённый ответ или отказ модели не приводят к побочному эффекту; пользователь получает просьбу уточнить.

Фраза о занятии с длительностью, но без дня считается запросом на планирование на сегодня в локальном часовом поясе. Приложение календаря всё равно требует подтверждения перед созданием события.

Используется текущий Groq-клиент и выделенная настройка `GROQ_PLANNING_API_KEY` вместе с `GROQ_PLANNING_MODEL`. Отдельный провайдер, ключ или общий automation framework не добавляются.

## Последствия

- Новая функция capture добавляется как capability с собственным сценарием, а не как новый классификационный блок внутри Telegram.
- Существующие authorization, journaling, idempotency и подтверждение календарного события остаются на своих местах.
- Поведение доступно только настроенному private chat; LLM не расширяет полномочия пользователя или чата.
- При недоступности Groq свободный текст безопасно не записывается, а команды продолжают работать.
