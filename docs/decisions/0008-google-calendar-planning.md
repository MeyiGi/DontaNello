# 0008: Планирование личных блоков времени через Google Calendar

Дата: 2026-10-04. Статус: принято.

## Контекст

Пользователь хочет предлагать время для личных занятий обычным сообщением в Telegram, учитывать существующую занятость и создавать блок только после подтверждения. Google Calendar должен оставаться единственным источником занятости. Личные календарные данные недопустимо открывать групповым чатам.

## Решение

Добавить отдельную capability `calendar_planning` с детерминированным разбором распространённых русских фраз. Опциональная вторая Groq-модель `openai/gpt-oss-20b` используется только как fallback для извлечения структуры сложных, но явно календарных запросов. Она не выбирает время и не выполняет действия. Модель прогресс-отчётов остаётся отдельной настройкой.

Прикладной сценарий читает Google Calendar через порт, строит максимум три слота в настраиваемом окне (по умолчанию 08:00–22:00, 15 минут буфера, `Asia/Bishkek`), отправляет inline-кнопки и перечитывает календарь при подтверждении. Запись одноразовая. Стабильный ID вместе с private extended property делают повтор создания идемпотентным; Undo удаляет только событие с соответствующим proposal identity.

Google OAuth запускается отдельно через CLI. Client secret остаётся локальным; token сохраняется в `state/` с режимом `0600`. Предложения хранятся в отдельной SQLite базе, а Telegram callback response использует текущий delivery journal, расширенный сохранением inline markup.

## Последствия

- Календарный сценарий тестируется без сети через порты и адаптеры.
- Пока не завершено OAuth-согласие владельца, календарь недоступен и события не создаются.
- Схема delivery journal обновляется с сохранением существующих сообщений и добавлением необязательного markup.
- В проект не добавляется фоновое или автоматически подтверждаемое размещение событий.
